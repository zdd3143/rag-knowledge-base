# 从零实现的 RAG 检索系统

> 不依赖任何 RAG 框架、从零手写的检索增强生成系统，面向石油石化领域文档问答。

## 这是什么

输入企业年报 PDF，能对里面的内容提问。核心链路：

**PDF 解析 → 分块 → 向量化 → 检索 →（后续）融合 → 重排 → 大模型生成**

## 为什么不用 LangChain

市面上 99% 的 RAG 项目是 `LangChain + Chroma + 一句话调用`，看不出任何工程细节。
这个项目**刻意不用框架**，每个环节自己实现，并配一套评估体系量化每一步的效果。

## 目前有什么发现

> 这一节是项目的重点——不是「我写了多少代码」，而是「我验证了什么、修了什么」。

**① 整份文档不能直接当向量**

BGE-M3 最大输入 8192 token，25 万字的年报会被**静默截断**。
实测：整份年报的向量与「只取前 8000 字」的向量相似度高达 **0.999**，
说明 8000 字之后的内容压根没进模型。→ 必须分块。

**② 纯向量检索分不清「答案」和「看起来像答案的东西」**

问题「中国石油2023年的营业收入是多少？」：

| 块 | 得分 | 排名 |
|---|---|---|
| 一张无关的子公司持股表 | 0.7404 | 第 1 |
| **正确答案所在块** | **0.7189** | **第 16** |

分差只有 **0.02** —— 纯向量区分不开「财务表格碎片」和「财务叙述答案」。

**③ BM25 能补上，但中文分词是前提**

手写 BM25（倒排索引 + 正 IDF）后，正确答案从第 16 名升到第 **4** 名。
但 jieba 把「营业收入」切成「营业/收入」、「中国石油」切成「中国/石油」，
两个最有区分度的词都废掉了。

加入 19 个石油财务领域词后：
`营业收入` 的 IDF 从 **0.5 升到 3.008**，正确答案升到第 **2** 名。

**④ IDF 是相对的，不是词的固有属性**

`中国石油` 在当前语料里 IDF 只有 **0.794**（出现在 45% 的块中）——
因为语料只有它一家的年报，公司名到处都是。
语料换成 30 家公司后，它自然会变成稀有词。

## 技术栈

Python · sentence-transformers (BGE-M3) · PyMuPDF · jieba · numpy

## 进度

- [x] 阶段 1：文本向量化 + 余弦相似度检索
- [x] 阶段 2：PDF 解析 + 分块（验证了截断问题）
- [x] 阶段 3：索引持久化 + numpy 矩阵化检索（**提速 325 倍**）
- [x] 阶段 4：手写 BM25 + 领域词表（正确答案排名 **16 → 2**）
- [ ] 阶段 5：混合检索（RRF 融合）+ cross-encoder 重排
- [ ] 阶段 6：接入大模型生成 + 引用溯源 + 拒答
- [ ] 阶段 7：评估体系（量化指标）
- [ ] 阶段 8：API 服务 + 演示界面

## 目录结构

```
src/
  stage1.py                最小 RAG：向量化 + 余弦相似度检索
  stage2_extract.py        PDF → 文本（PyMuPDF）
  stage2_chunk.py          文本 → 分块
  stage2_observe.py        验证「整份文档当向量会失效」
  stage3_build_index.py    建索引：编码 + 存盘
  stage3_search.py         检索 + numpy vs Python循环 速度对比
  stage3_diagnose.py       失败归因：正确答案排第几
  stage4_bm25.py           手写 BM25 + 领域词表
index/                     索引产物（不入库，可重建）
data/                      原始语料（不入库）
```

## 运行

```bash
pip install -r requirements.txt

# 1) 把年报 PDF 放进 data/raw/
python src/stage2_extract.py      # PDF → 文本
python src/stage2_chunk.py        # 文本 → 分块

# 2) 建索引（跑一次）
python src/stage3_build_index.py

# 3) 检索
python src/stage3_search.py       # 向量检索
python src/stage4_bm25.py         # BM25 检索
```
